The isolated app and XCTest host use `com.motovault.baseline.p00`; the existing
production Xcode project and main-source behavior were unchanged.

Runtime: fresh `MotoVault-P00-Baseline` simulator, iPhone 18 Pro Max, iOS 27.0,
UDID `639D8717-57E7-49B8-9DAA-2C365E2F1508`, 1320 x 2868 screenshot framebuffer,
440 x 956 window points. [Metadata](p00/platforms.json) records the bundle version,
runtime and installed executable hash. The pre-existing simulator and production
app were not used for fixture injection.

## Motion, Undo and the acceptance guard

[Native movie](p00/ios/motion-normal-and-reduced.mov) records gauge/count-up,
sheet, odometer save, attempted Undo and the reduced-motion sequence. The actual
final accepted run is [motion-r7](p00/ios/motion-r7-summary.json), with
[exported attachments](p00/ios/motion-r7/manifest.json). The gate was accepted
only after the rendered on-pill and committed flag agreed, not on a test-runner
pass alone.

[Undo observation](p00/ios/undo-observation.txt) records the expected 12340 and
observed 12350 after tapping Undo. [Durable state](p00/persistence-observations.json)
corroborates the non-restoring native behavior. It is an app defect, not a passing
Undo acceptance test.

The harness initially searched Button labels while some Compose controls expose
their visible label in an Other child of an unnamed Button. That trial failed
and its exported attachments remain under `p00/ios/motion/`. Other intermediate
captures finished but failed the real-state reduced-motion audit. They are not
accepted as proof that reduced motion was enabled. Scrolling and a zero-sized
accessibility frame required checking the actual rendered switch and a separate
durable payload observation. Retain that distinction in later UI testing.

Final reduced-motion evidence includes the visible on-state, the subsequent
sheet recording, and `outboxReduceMotion=true` in the isolated committed payload.
This last field corroborates the recorded in-session setting; Room's current
read mapper still does not restore it on relaunch.

The final harness uses a slow settled scroll, exact current palette colors and
fresh screenshots after every bounded touch attempt. It taps the labelled row's
body, requires the actual rendered on-pill and then checks durable data outside
the UI test. Earlier selector/toggle attempts remain diagnostic evidence and
are not counted as accepted reduced-motion runs.

## Reproduction and scope

`tools/baseline/p00.py prepare-ios-tests` copies the existing iOS host into ignored
`build/p00-ios-host/`, changes only its test identities/paths, and installs the
tracked `tools/baseline/P00BaselineTests.swift` harness. Build it with the current
scheme and `OVERRIDE_KOTLIN_BUILD_IDE_SUPPORTED=YES` after the native framework
build. `capture_ios.py` and `capture_ios_motion.py` retain result bundles under
ignored `build/` and export their labelled attachments into this evidence tree.
The scripts refuse to overwrite an existing result bundle; choose a new run
label when a recorded attempt needs correction.

This proves an iOS simulator baseline. It does not prove physical iPhone camera,
notification/background delivery, biometrics/key storage, battery use, crypto,
cloud isolation, signing or App Store publication. A successful capture test
proves capture/control execution, not every displayed behavior's correctness.
